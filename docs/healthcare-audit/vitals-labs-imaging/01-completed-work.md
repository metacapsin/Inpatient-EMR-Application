# Vitals / Labs / Imaging: Completed Work

Date: 2026-11-13. Phase 1, module 11. Full scope approved and implemented — SAF-15, BUG-13, SAF-25, SAF-26, plus structured imaging pregnancy/contrast-allergy safety fields. No external blocker.

## Summary for stakeholders

Vitals recorded respiratory rate and height from the start, but the form that enters them had those two fields commented out — both are now on the form and show up in the patient's vitals summary. The Labs tab used to show two different things side by side under one "Lab Results" heading: real structured results entered against a lab order, and an entirely separate, never-written-to document store left over from an earlier design — that dead second store is now removed, so the tab only shows real results. Lab test names are now matched against a real catalog (CBC, BMP, troponin, and 17 others) so an order's completion status is tracked by a stable code instead of only a loosely-matched name, and a single order that needs more than one specimen (for example blood and urine together) now tracks each specimen's own accession number instead of treating the whole order as one specimen. A code event's "generate clinical note" button only ever produced a preview the user could read and then lose — it now also has a "save as note" action that actually files a permanent, signable note in the patient's chart. Separately, a bug in how code events were filtered by unit meant the literal text "unit-1" was being treated as "show me every unit in the hospital" instead of an actual unit — fixed by using a real "all units" option instead of a magic string. Finally, an imaging order's pregnancy status and contrast-allergy status are now their own real, structured fields the system can act on (for example, flag a confirmed contrast allergy on an order that also requests contrast) — before this, pregnancy status was only ever flattened into a free-text instructions field, and contrast allergy wasn't captured on an order at all.

## Scope decisions (flagged, not silently cut)

- **Catalog is additive, not authoritative**: a lab test name outside the 20-entry catalog continues to work exactly as it did before (free-text name, matched by lowercased name at completion time). No UI was built to manage the catalog itself (it's a fixed seed list) — adding a 21st test today means a migration, not an admin screen.
- **Contrast-allergy surfaced as a table badge, not a hard order-time block**: the Imaging Orders table shows a red "Confirmed" / amber "Unknown" badge in a new Contrast Allergy column, but placing a contrast order against a confirmed allergy is not blocked at submission — flagging for visibility was judged the appropriate scope for this module; a hard interaction-style check would belong with the CDS rules engine (already used for medication interactions) and was not built here.
- **Legacy scalar specimen columns kept, not removed**: `lab_orders.accession_number`/`specimen_type` still exist and are kept in sync with the first specimen, purely for backward compatibility with any existing reader — `specimens` is the real source of truth going forward.
